# Authentication and credentials

Development uses `x-bot-buffet-user` only for local testing. Production mode requires a bearer JWT validated against `BOT_BUFFET_OIDC_ISSUER`, `BOT_BUFFET_OIDC_AUDIENCE`, and an HTTPS `BOT_BUFFET_OIDC_JWKS_URI` (or a pinned public `BOT_BUFFET_OIDC_JWKS_JSON` for controlled bootstrap/testing). Only RS256 keys with a matching `kid` are accepted; issuer, audience, authorized party, expiry, not-before, issued-at, optional nonce, and subject are validated before the subject becomes the actor ID. The loopback-only `bootstrap` mode accepts `BOT_BUFFET_BOOTSTRAP_TOKEN` for migration and never uses it as production identity. API keys/OAuth tokens are write-only inputs to the encrypted `CredentialVault` in local mode (or an external KMS/secret manager in production); the application stores provider, auth type, scopes, expiry, disabled state, and a fingerprint—not values. Provider creation also accepts `authType: "env"` with a validated `environmentVariable`; this stores only the reference (`env:NAME`) and resolves the value at adapter-use time, so the environment secret is never persisted or returned. OAuth 2.0 providers may declare authorization/token endpoints and use `POST /api/v1/providers/:id/oauth/start`; the server generates a one-time state and S256 PKCE verifier, returns only the authorization URL, and consumes the callback state once before exchanging the code. Device-capable providers may declare `deviceAuthorizationEndpoint`; `POST /api/v1/providers/:id/device/start` keeps the returned `device_code` server-side and returns only an actor-bound opaque `sessionId`, user code, verification URI, expiry, and bounded poll interval. `POST /api/v1/providers/:id/device/poll` maps `authorization_pending`/`slow_down` without returning provider bodies, exchanges the code server-side, and stores only encrypted credential material plus metadata. Device sessions are actor/provider-bound, memory-bounded, expire within 15 minutes, and enforce poll backoff. Authorization endpoints, device/verification URIs, token endpoints, and non-loopback redirects require HTTPS; callback/device state is actor-bound. When no development master key is supplied, the vault creates a random 32-byte key beside the credential file with restrictive permissions; this key is not included in backups and must be provisioned separately for restore. Rotation is connect-new → test → switch route → revoke-old → audit.
