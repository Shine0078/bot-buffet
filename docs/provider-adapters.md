# Provider adapter guide

`ModelAdapter` normalizes completion, health, model listing, usage, latency, tool calls, and structured output. `OpenAICompatibleAdapter` supports localhost servers and OpenAI-compatible gateways. Anthropic and Gemini use dedicated adapters with their native message, authentication, usage, and response formats; unsupported capabilities remain explicit rather than silently being treated as OpenAI-compatible. All provider requests use the pinned socket transport: DNS preflight rejects private/metadata addresses, then the selected address is passed directly to the connection while the original hostname remains the Host/SNI value. The provider API supports health testing and revocation. Store only credential fingerprints and expiry/scopes in entities; the local `CredentialVault` encrypts values at rest and production must replace it with an OS keychain/KMS/secret manager.

To add a provider: define capability detection, typed error mapping, health/list probes, auth test and revocation behavior, redaction tests, contract tests with a real sandbox account, and routing metadata. Update `docs/owner-gates.md` with the credential owner and expiry process.
