# Provider adapter guide

`ModelAdapter` normalizes completion, streaming chunks, embeddings where supported, bounded client-side batching, health, model listing, usage, latency, tool calls, and structured output. `OpenAICompatibleAdapter` supports localhost servers and providers that explicitly expose the OpenAI chat-completions contract (OpenAI, xAI, OpenRouter, Mistral, DeepSeek, Together, Fireworks, and compatible gateways). Its pinned streaming transport delivers response chunks as they arrive, parses OpenAI SSE frames into a bounded normalized async iterable, its embeddings path validates every returned vector, and its batch path caps fan-out at 32 requests. Anthropic, Gemini, Azure OpenAI, Cohere, and Bedrock expose the same streaming and batching contracts through normalized final-response/concurrent fallbacks when native provider batch or streaming wire formats are not enabled yet; Cohere additionally normalizes `/v2/embed` vectors. Anthropic and Gemini use dedicated adapters with their native message, authentication, usage, and response formats. Cohere uses a native v2 adapter: it sends `/v2/chat` requests with bearer authentication, preserves system/user/assistant/tool roles, maps response content/tool calls/usage, and probes `/v1/models`. The adapter omits Cohere's `response_format` when tools are present because that combination is rejected by the provider. Azure OpenAI uses a deployment-scoped adapter with `api-key` authentication, configurable API version, deployment health/model probes, and normalized chat responses. Amazon Bedrock uses the Converse API with AWS SigV4 signing, region-aware control-plane model probes, normalized system/messages/tools/tool-use blocks, and credentials supplied as an encrypted JSON vault value (`accessKeyId`, `secretAccessKey`, optional `sessionToken`/`region`) or the standard AWS environment variables. Unsupported capabilities remain explicit rather than silently being treated as equivalent.

All provider requests use the pinned socket transport: DNS preflight rejects private/metadata addresses, then the selected address is passed directly to the connection while the original hostname remains the Host/SNI value. The provider API supports health testing and revocation. Store only credential fingerprints and expiry/scopes in entities; the local `CredentialVault` encrypts values at rest and production must replace it with an OS keychain/KMS/secret manager.

To add a provider: define capability detection, typed error mapping, health/list probes, auth test and revocation behavior, redaction tests, contract tests with a real sandbox account, and routing metadata. Update `docs/owner-gates.md` with the credential owner and expiry process.
