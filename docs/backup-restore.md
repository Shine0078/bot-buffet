# Backup and restore

Local state is the `.data/state.json` file and encrypted credentials are `.data/credentials.enc.json`; use `npm run backup -- ./backup-2026-08-21` while the service is stopped. The development vault key is `.data/credentials.enc.json.key`; it is random, deliberately excluded from backups, and must be supplied separately when restoring encrypted credentials. When `BOT_BUFFET_BACKUP_KEY` (or the master key) is present, `state.json` is wrapped with AES-256-GCM and the backup also writes `manifest.mac`, an HMAC-SHA-256 signature over the exact versioned manifest bytes. Production requires a 32-byte key, an encrypted state file, and a signed manifest; the scripts reject plaintext production state backups. `npm run restore -- ./backup-2026-08-21` verifies the ciphertext hash, authenticates/decrypts the state, and verifies the manifest signature before promotion. Restore to a new project/tenant, provision the vault key or production KMS binding before starting the service, verify object and audit hashes, run migrations, verify `/readyz`, execute a golden task and permission tests, then promote by changing traffic—not by overwriting the only copy.
