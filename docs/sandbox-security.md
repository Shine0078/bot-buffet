# Sandbox security guide

Each run receives a project-root workspace and an allowlist/protected-path policy from its agent profile. Filesystem tools reject null bytes, absolute paths, traversal, symlink escapes (including the write parent), protected descendants such as `.git/**` and `.env*`, disallowed paths, oversized writes, and output over the contract limit. Shell execution rejects shell metacharacters, code-execution and workspace-escape flags, permits only read-only version/help probes, enforces a 30-second timeout and 1 MB output cap, and blocks network-shaped commands when the effective environment network is blocked. Development uses the explicit `BOT_BUFFET_SANDBOX_MODE=local` fallback. Production refuses to start unless `BOT_BUFFET_SANDBOX_MODE=docker` is selected; built-in file and shell operations then run through a disposable Docker invocation with a read-only root filesystem, no network, dropped capabilities, `no-new-privileges`, PID/CPU/memory limits, a non-root UID, and only the project workspace bind-mounted.

## Image pinning

The sandbox image is the boundary that contains agent-generated code, so in production it must be immutable. `BOT_BUFFET_SANDBOX_IMAGE` must be a digest-pinned reference of the form `name@sha256:<64 hex>`; a registry, port, and path may precede the digest. Production fails closed at startup — an unset image raises `sandbox_image_required` and a tag-only image raises `sandbox_image_not_pinned` — rather than falling back to a default, because a sandbox whose contents can change between runs is not a boundary anyone can reason about. Development keeps the unpinned default, where the workspace is disposable.

Resolve a digest with `docker buildx imagetools inspect <image>` and record it alongside the release. Re-pin deliberately when the base image is updated; do not automate it, or the pin stops meaning anything.

The checked-in Docker runtime is the local container implementation. A production owner must provide the Docker/microVM runner, mount policy, image provenance, credential injection, egress policy, artifact scanning, snapshot/rollback, and escape-test evidence before enabling production runs. Network modes other than `blocked` are deliberately rejected until an egress proxy/allowlist is supplied. Never treat a local model as trusted merely because it is local.
